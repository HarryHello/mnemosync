## 1. 概述 (Overview)

Mnemosync 的记忆系统是整个项目的核心，负责实现**跨平台人格记忆同步**。

### 1.1 核心价值

```
┌─────────────────────────────────────────────────────────────┐
│  Mnemosync 记忆同步原理                                      │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  前端 A (AstrBot)     前端 B (AIRI)     前端 C (Web)        │
│  "我叫马达"          "我压力大"        "你喜欢什么"        │
│       ↓                  ↓                  ↓               │
│       └──────────────────┼──────────────────┘               │
│                          ↓                                   │
│              ┌───────────────────────┐                      │
│              │   Mnemosync 记忆池     │                      │
│              │  ┌─────────────────┐  │                      │
│              │  │ 马达的完整记忆   │  │ ← 统一的人格记忆     │
│              │  │ - 叫马达        │  │    不是分散的会话日志 │
│              │  │ - 压力大        │  │                      │
│              │  │ - 喜欢...       │  │                      │
│              │  └─────────────────┘  │                      │
│              └───────────────────────┘                      │
│                          ↓                                   │
│              不管哪个前端来对话                              │
│              都记得"马达压力大"                              │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **记忆不是为了隔离数据** | 而是为了在合适的语境下，唤起合适的记忆 |
| **重要性与持久性分离** | 重要的事不一定永久，永久的事不一定重要 |
| **衰减不等于遗忘** | 衰减是优先级降低，遗忘是彻底删除 |
| **永久记忆需要限额** | 避免上下文混乱，保证核心信息不丢失 |

## 2. 记忆分类 (Memory Classification)

### 2.1 双类型系统

```
记忆系统
├── 永久记忆 (PERMANENT)
│   ├── 核心记忆 (importance=1.0) - 不可覆盖
│   └── 偏好记忆 (importance=0.5) - 可覆盖
│
└── 普通记忆 (NORMAL)
    ├── 重要性 (importance: 0.0-1.0)
    ├── 衰减速率 (decay_rate: 0.0-1.0)
    └── 过期时间 (expires_at: optional)
```

**核心洞察**：
- **重要性 ≠ 持久性**
  - "明天开会"：重要但短期
  - "喜欢蓝色"：不重要但长期
- **衰减 ≠ 遗忘**
  - 衰减：优先级降低，不主动想起
  - 遗忘：彻底删除，搜索也找不到

---

### 2.2 永久记忆 (Permanent Memory)

**定义**：不衰减的记忆，除非被覆盖或删除。

| 类型 | 重要性 | 可覆盖 | 例子 |
|------|--------|--------|------|
| **核心记忆** | 1.0 | ❌ 否 | 用户名字、过敏信息 |
| **偏好记忆** | 0.5 | ✅ 是 | 喜好、习惯、偏好 |

**限额机制**：
- 永久记忆上限：**15 条**
- 超出时：覆盖最少访问的偏好记忆
- 核心记忆永不被覆盖

**小模型分析策略**（保守）：
```
✅ 存储为永久记忆:
- 用户名字、昵称
- 过敏、禁忌（健康相关）
- 明确说"永远记住"

❌ 不存储为永久记忆:
- 一般偏好 → 普通记忆
- 临时信息 → 普通记忆
- 日常闲聊 → 不存储或普通记忆
```

---

### 2.3 普通记忆 (Normal Memory)

**定义**：遵循衰减模型的记忆，优先级随时间降低。

**核心参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `importance` | 0.0-1.0 | 基础重要性 |
| `decay_rate` | 0.0-1.0 | 衰减速率（0=不衰减，1=快速衰减） |
| `expires_at` | datetime | 过期时间（可选） |

**衰减半衰期**：
```
decay_rate = 0.1 → 半衰期 91 天（长期记忆）
decay_rate = 0.5 → 半衰期 51 天（中期记忆）
decay_rate = 0.9 → 半衰期 11 天（短期记忆）
```

**过期机制**：
- 过期后重要性降至 1%
- 数据不删除，搜索时可恢复
- 类比：人类"想不起来但看到能记起"

---

## 3. 衰减模型 (Decay Model)

### 3.1 优先级计算

记忆优先级决定是否会出现在对话上下文中。

**计算公式**：
```
优先级 = 重要性 × 衰减因子 × 过期惩罚 + 访问加成

其中:
- 衰减因子 = 0.5^(经过天数 / 半衰期)
- 过期惩罚 = 0.01 (如果过期) 或 1.0 (未过期)
- 访问加成 = log(访问次数 + 1) × 0.05
```

**永久记忆**：优先级恒为 1.0（始终出现在上下文中）

---

### 3.2 遗忘阈值

```
优先级 > 0.05 → 活跃记忆（会出现在上下文中）
优先级 ≤ 0.05 → 遗忘记忆（不主动出现，搜索可恢复）
```

**生物学类比**：
- 活跃记忆 = 短期/工作记忆
- 遗忘记忆 = 长期记忆（需要提示才能想起）

---

### 3.3 访问加成

经常被访问的记忆衰减更慢：

```
访问次数    访问加成
0          +0.00
1          +0.03
5          +0.09
20         +0.16
```

**设计意图**：模拟人类"常用不忘"的特性

---

## 4. 上下文合并 (Context Merging)

### 4.1 合并策略

发送给上游模型的消息由三部分组成：

```
┌─────────────────────────────────────────┐
│  [0] system: 人格提示词                  │
│  [1] system: 永久记忆（最多 7 条）        │
│  [2+] user/assistant: 普通记忆 + 当前消息 │
└─────────────────────────────────────────┘
```

**记忆位置**：放在 system prompt 末尾，与人格提示词合并为一个消息。

**理由**：
- 避免多个 system 消息导致模型混淆
- 记忆作为"背景知识"而非"对话内容"

---

### 4.2 查询流程

```
1. 获取所有记忆
       ↓
2. 分离永久记忆和普通记忆
       ↓
3. 永久记忆：按重要性排序，取前 7 条
       ↓
4. 普通记忆：计算优先级，过滤 < 0.05
       ↓
5. 普通记忆：按优先级排序，取前 13 条
       ↓
6. 合并：永久记忆 (7) + 普通记忆 (13) = 20 条
```

**上下文配额**：
- 永久记忆：最多 50%（保证核心信息）
- 普通记忆：最少 50%（保证相关性）

## 5. 记忆生命周期 (Memory Lifecycle)

### 5.1 创建流程

```
用户消息
   ↓
小模型分析
   ├─→ 是否永久记忆？
   ├─→ 重要性 (0.5/1.0)
   ├─→ 衰减速率 (0.0-1.0)
   └─→ 过期时间（如有）
   ↓
检查永久记忆限额
   ├─→ 未满 → 直接保存
   └─→ 已满 → 查找可覆盖的偏好记忆
           ├─→ 找到 → 覆盖
           └─→ 未找到 → 拒绝保存（降级为普通记忆）
   ↓
存储到数据库
```

---

### 5.2 衰减流程

```
定期执行（每天凌晨）
   ↓
遍历所有普通记忆
   ↓
计算当前优先级
   ↓
标记优先级 < 0.05 为"遗忘"
   ↓
（可选）删除过期 > 30 天的记忆
```

---

### 5.3 访问流程

```
查询记忆时
   ↓
被选中的记忆
   ↓
access_count += 1
last_accessed = now
   ↓
优先级提升（访问加成）
```

---

## 6. 关键设计决策 (Key Design Decisions)

### 6.1 为什么永久记忆需要限额？

**问题**：如果不限额，永久记忆会无限增长，导致：
- 上下文 token 浪费
- 重要信息被稀释
- 模型注意力分散

**解决**：
- 限额 15 条
- 核心记忆（名字、过敏）不可覆盖
- 偏好记忆可被新偏好覆盖

---

### 6.2 为什么重要性与持久性分离？

**错误设计**：
```
重要 = 长期记忆
不重要 = 短期记忆
```

**问题**：
- "明天开会"重要但应该短期
- "喜欢蓝色"不重要但应该长期

**正确设计**：
```
重要性 → 决定初始优先级
持久性 → 决定衰减速度
过期时间 → 决定何时骤降优先级
```

---

### 6.3 为什么衰减不等于遗忘？

**生物学类比**：
- 人类不会真正"删除"记忆
- 只是优先级降低，不主动想起
- 但被提示时能恢复

**工程实现**：
- 优先级 < 0.05 标记为"遗忘"
- 数据不删除
- 搜索/查询时可恢复

**好处**：
- 模拟人类记忆特性
- 用户说"我之前说过..."时能找到
- 避免永久删除导致的信息丢失

---

### 6.4 为什么小模型分析要保守？

**激进策略的问题**：
- 永久记忆快速增长
- 限额很快达到
- 真正重要的信息可能被覆盖

**保守策略**：
- 只有核心信息（名字、过敏）才永久
- 一般偏好用普通记忆（衰减模型）
- 日常闲聊不存储或短期存储

**效果**：
- 永久记忆增长缓慢
- 限额长期有效
- 核心信息永久保留
