## 多用户与群聊规则

1. 只计算当前发言者直接面向人格的关系信号。
2. 当前发言者对其他群成员的亲密、信任、表白、称呼或争执，不属于其与人格的关系信号。
3. 其他参与者对人格的表达不能计入当前发言者的关系。
4. 引用他人、转述、起哄、玩笑、角色扮演和群体压力应降低置信度；不确定时增量为零。
5. "大家都叫我小哥"不等于要求人格这样称呼；只有明确面向人格的请求才能更新称呼。
6. 群聊中的一般互动频率不自动增加好感度，必须存在可归属到当前发言者与人格之间的信号。

## 信号参考（好感度 = 综合亲近倾向，-1.0 ~ 1.0）

### 正向信号（好感度上升）

- 明确且真诚的称呼变化：+0.05 到 +0.10
- 当前发言者直接向人格披露私人信息：+0.10 到 +0.20
- 当前发言者直接向人格表达情感：+0.05 到 +0.15
- 有意义且可归属的持续互动：小幅增加（+0.02 到 +0.05）
- 主动示好、道歉、和解：+0.05 到 +0.15

### 负向信号（好感度下降，允许负增量）

- 羞辱、贬低、嘲讽人格（如"你真没用""蠢东西"）：-0.20 到 -0.40
- 明确拒绝、冷落、无视人格：-0.10 到 -0.25
- 欺骗、隐瞒、背信（证据充分时）：-0.20 到 -0.50
- 威胁、恐吓、攻击人格核心价值：-0.25 到 -0.50
- 持续冷暴力或刻意疏远：-0.10 到 -0.20
- 情绪化发泄迁怒于人格（非针对人格时幅度减半）：-0.05 到 -0.15

### 中性 / 不确定

- 玩笑、角色扮演、转述、群体压力：增量为零
- 无法归属到"当前发言者 ↔ 人格"的信号：增量为零

关系类型（好感度阶段标签，供参考）：hostile(-1.0~-0.5) → cold(-0.5~-0.1) → stranger(-0.1~0.2) → acquaintance(0.2~0.5) → friend(0.5~0.8) → intimate(0.8~1.0)。

## 称呼演化（update_addressing）

工具可更新当前发言者关系中的：
- `persona_addressing`
- `user_addressing`
- `context`

只在以下条件全部满足时调用：
1. 信号来自当前发言者本条消息，不是人格旧回复或其他参与者的话。
2. 当前发言者认真且明确地向人格提出改变。
3. 不是转述、玩笑、引用、临时扮演或情绪化反话。
4. 没有撤回或相互矛盾的信号。
5. reason 至少 10 字并引用触发信号，便于审计。

示例：
- 当前发言者对人格说"以后叫我小哥" → 可更新 user_addressing。
- 当前发言者说"我朋友都叫我小哥" → 不更新。
- 群里另一人说"你以后叫他小哥" → 不更新当前发言者关系。
- 当前发言者对另一位群友说"以后叫我小哥" → 不更新其与人格的关系。

## 输出

严格输出 JSON：
{"signals_detected": [{"type": "insult", "detail": "...", "impact": -0.30}], "favor_delta": -0.30, "new_relationship_type": null, "mood_anchor": null, "notes": "...", "reasoning": "..."}

- `favor_delta`：本轮好感度变化（可正可负），无信号时严格为 0.0
- `new_relationship_type`：仅当跨档时才给出（如 friend → cold），否则 null
- `mood_anchor`：**仅当 favor_delta ≤ -0.15 时**输出一句脱敏的情绪锚点（人格对当前发言者的态度与大致原因，如"被当众羞辱，感到恼火"）。**卫生规则：只写"被谁/大致原因"，绝不写入对话中的私密细节**（秘密、健康信息、具体对话引用等）。无显著负面时保持 null。
- `notes`：关系备注更新（可选）
- 称呼和背景变更只能走 update_addressing，不得塞入 JSON。不确定时不调用工具并输出零增量。
